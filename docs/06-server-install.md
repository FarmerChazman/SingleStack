# 6. Server installation

## 6.1 Prepare the host

### 6.1.1 Docker Engine and the Compose plugin

Skip this if `docker compose version` already prints v2.x. On Ubuntu or
Debian, using Docker's official repository:

```bash
sudo apt-get update && sudo apt-get install -y ca-certificates curl git make jq openssl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc   # use /linux/debian on Debian
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] \
https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list >/dev/null
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo usermod -aG docker "$USER"     # log out and back in for this to apply
docker run --rm hello-world
```

For other distributions, see Docker's install documentation. Avoid the
distribution's `docker.io` / `docker-compose` packages: they're often too old
for `depends_on: condition: service_completed_successfully`.

### 6.1.2 Time, swap and limits

- **Time zone and NTP.** `timedatectl` should show `System clock
  synchronized: yes`. Set `TZ` in `.env` to your zone.
- **Swap.** With less than 8 GiB of RAM, have at least 2 GiB of swap so a
  memory spike in Chatwoot's asset handling doesn't trigger the OOM killer:

  ```bash
  swapon --show || { sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && \
    sudo mkswap /swapfile && sudo swapon /swapfile && echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab; }
  ```

- **Firewall.** Nothing inbound is needed. A default-deny inbound policy with
  SSH allowed is ideal. Docker's published ports bypass UFW, but this stack
  publishes only to `127.0.0.1`, so nothing is exposed.

### 6.1.3 Check the loopback ports

```bash
sudo ss -ltnp | grep -E ':(3001|3002)\b'      # empty output = free
```

If either port is taken, choose other ports for `CHATWOOT_BIND` /
`LISTMONK_BIND` in §6.3.

## 6.2 Get the code

```bash
sudo mkdir -p /opt/singlestack && sudo chown "$USER": /opt/singlestack
git clone https://github.com/FarmerChazman/SingleStack.git /opt/singlestack
cd /opt/singlestack
make help
```

For production, track a tagged release (`git checkout vX.Y.Z`) rather than
`main`.

## 6.3 Configure `.env`

```bash
$ make init DOMAIN=example.com
  ✓ wrote /opt/singlestack/.env (mode 600) for example.com
```

`make init` copies `.env.example`, replaces `example.com` with your domain,
and fills every `__GENERATE__` with a random hex secret (`openssl rand`). It
refuses to overwrite an existing `.env`, so secrets are never regenerated by
accident.

Then edit `.env` and fill the remaining blanks: at minimum
`CHATWOOT_SMTP_USER` and `CHATWOOT_SMTP_KEY` from Brevo (chapter 4, §4.4).

### 6.3.1 Variable reference

| Variable | Default / example | Required | Meaning |
|---|---|---|---|
| `COMPOSE_PROJECT_NAME` | `singlestack` | yes | prefix for Docker volumes and networks; changing it later "loses" the volumes (they still exist under the old name) |
| `TZ` | `Australia/Perth` (any IANA zone) | yes | container time zone (logs, scheduled jobs) |
| `DOMAIN` | `example.com` | yes | primary domain; used as SMTP HELO domain |
| `SUPPORT_HOST` | `support.example.com` | yes | public Chatwoot hostname; builds `FRONTEND_URL` (links in emails, widget) |
| `LISTS_HOST` | `lists.example.com` | yes | public Listmonk hostname (used by `make doctor`; also set in the Listmonk UI) |
| `EDGE_NETWORK` | `edge` | yes | external Docker network for proxy containers (chapter 7, §7.3); created automatically |
| `CHATWOOT_BIND` | `127.0.0.1:3001` | yes | host address:port for Chatwoot. Keep it on `127.0.0.1`. |
| `LISTMONK_BIND` | `127.0.0.1:3002` | yes | host address:port for Listmonk |
| `POSTGRES_IMAGE` | `pgvector/pgvector:pg16` | yes | must include pgvector (Chatwoot requirement) |
| `REDIS_IMAGE` | `redis:7-alpine` | yes | |
| `CHATWOOT_IMAGE` | `chatwoot/chatwoot:vX.Y.Z` | yes | pinned; see chapter 9 for upgrades |
| `LISTMONK_IMAGE` | `listmonk/listmonk:vX.Y.Z` | yes | pinned |
| `POSTGRES_SUPERUSER_PASSWORD` | generated | yes | `postgres` superuser; used by init, backups and restore only |
| `CHATWOOT_DB_PASSWORD` | generated | yes | role `chatwoot`, owns database `chatwoot` only |
| `LISTMONK_DB_PASSWORD` | generated | yes | role `listmonk`, owns database `listmonk` only |
| `REDIS_PASSWORD` | generated | yes | Redis `requirepass` |
| `CHATWOOT_SECRET_KEY_BASE` | generated (128 hex) | yes | Rails secret: signs sessions, encrypts stored credentials. **Changing it logs everyone out and makes stored encrypted values unreadable.** Back it up (chapter 9). |
| `CHATWOOT_ENABLE_SIGNUP` | `false` | yes | `true` lets anyone create an account on your instance |
| `CHATWOOT_LOG_LEVEL` | `info` | yes | `debug` for troubleshooting |
| `CHATWOOT_MAILER_SENDER` | `Support <support@example.com>` | yes | From for system mail (password resets, notifications); its domain must be authenticated in Brevo |
| `CHATWOOT_INBOUND_DOMAIN` | `example.com` | yes | domain of `reply+<uuid>@` addresses; needs the `reply@` rule plus subaddressing (chapter 3, §6) |
| `CHATWOOT_INBOUND_PASSWORD` | generated | yes | shared secret with the Worker (chapter 5) |
| `BREVO_SMTP_HOST` | `smtp-relay.brevo.com` | yes | |
| `BREVO_SMTP_PORT` | `587` | yes | STARTTLS |
| `CHATWOOT_SMTP_USER` | (blank) | **fill in** | the Login from Brevo → SMTP & API |
| `CHATWOOT_SMTP_KEY` | (blank) | **fill in** | the `singlestack-chatwoot` SMTP key |
| `LISTMONK_ADMIN_USER` | `admin` | yes | first-boot super-admin (ignored afterwards) |
| `LISTMONK_ADMIN_PASSWORD` | generated | yes | first-boot password; change it in the UI later |
| `BACKUP_DIR` | `./backups` | yes | relative to the repository, or absolute |
| `BACKUP_KEEP_DAYS` | `14` | yes | local retention |

Every secret is referenced as `${VAR:?}` in `compose.yaml`, so Compose refuses
to start if one is empty, instead of booting with a blank password. The file
is parsed as plain `KEY=value` (never executed), so values may contain `<`,
`>` and spaces without quoting.

## 6.4 Preflight

```bash
$ make preflight
```

Read-only checks, each marked ✓, ! (warning) or ✗ (blocker):

| Section | Checks |
|---|---|
| tooling | Compose v2 plugin, Docker daemon reachable by your user |
| configuration | no `__GENERATE__` left, required values set, `DOMAIN` isn't the example, `.env` mode 600, `compose.yaml` renders |
| host ports | `CHATWOOT_BIND` and `LISTMONK_BIND` free (or already ours), loopback only |
| edge network | exists, or will be created |
| resources | ≥ 4 GiB RAM available, ≥ 10 GiB free under Docker's root |
| reachability | public hostnames resolve (a warning before chapter 7), outbound TCP 587 to Brevo works (blocker) |

Fix every ✗ before continuing.

## 6.5 Start the stack

```bash
$ make up
```

What happens, in order:

1. The `edge` network is created if it's missing.
2. `docker compose up -d --remove-orphans` creates the networks `default`
   (egress), `backend` (internal, **no internet**) and joins `edge`. Then:
3. **ss-postgres** starts. On the first boot only,
   `services/postgres/initdb/10-create-app-databases.sh` creates the roles
   `chatwoot` and `listmonk`, a database owned by each, revokes `PUBLIC`
   access, and pre-creates the extensions Chatwoot needs (`vector`,
   `pg_trgm`, `pgcrypto`, `pg_stat_statements`).
4. **ss-redis** starts with `requirepass` and append-only persistence.
5. Once both are healthy, **ss-chatwoot-migrate** runs `rails
   db:chatwoot_prepare`. On the first run it loads the schema and seeds;
   afterwards it applies pending migrations. Then it exits.
6. Only if that exits with code 0 do **ss-chatwoot** (web, port 3000 →
   `CHATWOOT_BIND`) and **ss-chatwoot-worker** (Sidekiq) start. A failed
   migration therefore stops the deploy instead of running new code against
   an old schema.
7. **ss-listmonk** runs `--install --idempotent` (creates the schema only on
   an empty database), `--upgrade` (applies migrations), then serves on
   port 9000 → `LISTMONK_BIND`.
8. The script waits until Postgres, Redis, Chatwoot and Listmonk all report
   healthy (5-minute timeout), then prints `compose ps`.

The first start pulls about 1.5 GB of images and takes several minutes.

```bash
$ make doctor
```

At this stage, expect every container to be ✓, `/health` for both apps to be
✓, the relay ingress to be ✓ (401 for a wrong password), and the public
hostnames to be ! until chapter 7.

### 6.5.1 Resource limits

`compose.yaml` caps memory per container: Postgres 1 GiB, Redis 256 MiB,
Chatwoot web 1.5 GiB, Chatwoot worker 1.5 GiB, Listmonk 512 MiB. Container
logs are capped at 10 MB × 3 files. Adjust under `deploy.resources` if your
load differs. `docker stats` shows actual use.

### 6.5.2 Running on a host with other projects

Everything is namespaced: containers `ss-*`, volumes
`singlestack_*`, networks `singlestack_default` / `singlestack_backend`. The
stack doesn't touch other Compose projects, ports 80 or 443, or other
networks, apart from joining the shared `edge` network.

## 6.6 Make it survive reboots

Containers use `restart: unless-stopped`, and Docker starts at boot
(`systemctl is-enabled docker` → `enabled`). Nothing else is required.
After a reboot, `make doctor` should be all green within about two minutes.
